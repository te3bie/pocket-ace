# Completion and verification ledger

This is a runnable implementation with a local demo and deployable backend source. It is **not marked complete or production verified**. Every requested area is accounted for below. No live credentials were supplied, no paid service was provisioned, and no student data was sent to a provider during implementation.

Status vocabulary: **Implemented** means code is present; **Verified** names a check actually executed; **Blocked by external dependency** means credentials, infrastructure/device or independent review are required; **Awaiting product decision** means a material launch choice is unresolved. Code presence alone does not prove a live integration.

## Executed evidence

- `npm run typecheck`: passes.
- `npm test`: 15 domain cases (money, recurrence, dates, paid snapshot preservation, DST, CSV, catalog validation and malformed-state rejection).
- `npm run build`: exports all routes to `dist`.
- `npm run backend:check`: all three Edge Function entrypoints pass Deno type checks.
- `npm run test:backend`: 11 real HTTP handler checks with local mocked Auth/RPC pass. These are not real Supabase database/provider tests.
- `npm run test:journeys`: balance edit; expense create/edit/paid/undo/delete; saved opportunity/status; profile reload persistence; scripted demo chat/deletion; CSV import/dedup pass, no browser runtime errors.
- `npm audit`: zero known advisories after patched glob/minimatch overrides. Expo module compatibility checked; AsyncStorage aligned.

Screenshots and checks must be rerun after changes. Tests for actual database isolation, live email/MFA recovery, provider AI and Sandbox transactions, valid signed webhook delivery, native notification delivery and store builds remain blocked. No claim of production readiness is made.

## Material launch decisions

Awaiting product decision: hosting/provider plans and regions/billing, AI provider and minor-user processing/retention consent, age/guardian policy and legal review, verified support contact/domain, catalog review responsibility/source permissions, university advertising terms and invoice/fraud process. Student subscriptions remain absent.

## Known implementation limits

Account state uses one private JSON document and last-write-wins multi-device synchronization; there is no offline merge queue or automatic imported-transaction reconciliation. Bank UI supports one item per user, sandbox only. Provider-hosted banking completion and reconnect require credentials and a reachable signed webhook. Advanced ML, push notifications, background notification renewal, automated source scraping, automated fraud scoring and invoicing are not implemented. Native TOTP setup uses a copyable secret rather than a QR image. Admin currently edits validated catalog/campaign JSON; a guided bulk-ingestion form is future work. Optional tuition/living-cost comparison and semester scenario tools were deprioritized to preserve core scope.
